What is a JWT?

      
A JSON Web Token is a compact, URL-safe string that carries a small JSON document between two systems — most often a login session passed from an auth server to an API. It has three parts separated by dots: header.payload.signature. The first two are just base64url-encoded JSON, which is why anyone holding the token can read them with a tool like this one.

      
How to read it

      
    
        
  • Header — metadata, mainly alg (how it was signed, e.g. HS256 or RS256) and sometimes kid, the ID of the signing key.
    • 
        
  • Payload — the claims. Registered names are short on purpose: iss issuer, sub subject, aud audience, exp expiry, nbf not-before, iat issued-at and jti token ID. Times are in seconds since 1 January 1970 (UTC); the table above turns them into real dates.
    • 
        
  • Signature — proof that the first two parts were created by someone holding the key and have not been changed since.
    • 
      

      
Decoding is not verifying

      
Reading a payload tells you what a token claims, not whether the claims are true. An attacker can edit the payload and re-encode it in seconds; only the signature check exposes that. Your server must always verify the signature with a fixed, expected algorithm — never trust the alg field blindly, and reject alg: none. Also remember that the payload is not encrypted: do not put passwords or personal data in it.

      
FAQ

      
Is it safe to paste a real token here?
The page works offline once loaded and sends nothing anywhere. Still, treat live tokens like passwords: prefer expired or test tokens, and never paste a private key — verification only needs the public key.

      
Why does my app accept a token this page calls expired?
Many libraries allow a little clock skew (often 30–120 seconds), and your device clock may differ from the server’s.

      
My token has five parts.
That is an encrypted JWE. Only the header is readable; the content needs the recipient’s private key.

      
Verification says my key format is wrong.
Use an SPKI key that starts with BEGIN PUBLIC KEY, or a public JWK. A certificate or a BEGIN RSA PUBLIC KEY key must be converted first (for example with openssl).

    

    

      
JWT কী?

      
JSON Web Token হলো ছোট, URL-এ নিরাপদে পাঠানো যায় এমন একটি স্ট্রিং, যা দুটি সিস্টেমের মধ্যে ছোট্ট একটি JSON ডকুমেন্ট বহন করে — সাধারণত লগইন সেশনের তথ্য, যা অথ সার্ভার থেকে API-তে যায়। এর তিনটি অংশ থাকে, ডট দিয়ে আলাদা: header.payload.signature। প্রথম দুটি অংশ কেবল base64url-এ এনকোড করা JSON, তাই টোকেন যার হাতে আছে সে-ই এই ধরনের টুল দিয়ে এগুলো পড়তে পারে।

      
কীভাবে পড়বেন

      
    
        
  • হেডার — মেটাডেটা, মূলত alg (কোন পদ্ধতিতে সাইন করা, যেমন HS256 বা RS256) আর কখনো kid, অর্থাৎ সাইনিং কী-এর আইডি।
    • 
        
  • পেলোড — ক্লেইমগুলো। নিবন্ধিত নামগুলো ইচ্ছে করেই ছোট: iss ইস্যুকারী, sub বিষয় (সাধারণত ইউজার আইডি), aud কার জন্য, exp মেয়াদ শেষ, nbf কখন থেকে বৈধ, iat তৈরির সময় আর jti টোকেনের আইডি। সময়গুলো ১৯৭০ সালের ১ জানুয়ারি (UTC) থেকে সেকেন্ডে গোনা; ওপরের টেবিল এগুলোকে আসল তারিখে দেখায়।
    • 
        
  • সিগনেচার — প্রমাণ যে প্রথম দুটি অংশ কী-এর মালিকই তৈরি করেছে এবং এরপর কেউ বদলায়নি।
    • 
      

      
ডিকোড করা মানেই যাচাই করা নয়

      
পেলোড পড়লে জানা যায় টোকেনটি কী দাবি করছে, দাবিগুলো সত্যি কি না তা নয়। আক্রমণকারী কয়েক সেকেন্ডেই পেলোড বদলে আবার এনকোড করতে পারে; কেবল সিগনেচার যাচাই করলেই সেটা ধরা পড়ে। আপনার সার্ভারে সবসময় নির্দিষ্ট, প্রত্যাশিত অ্যালগরিদম দিয়ে সিগনেচার যাচাই করুন — alg ফিল্ডকে অন্ধভাবে বিশ্বাস করবেন না, আর alg: none টোকেন বাতিল করুন। মনে রাখবেন পেলোড এনক্রিপ্ট করা থাকে না: এতে পাসওয়ার্ড বা ব্যক্তিগত তথ্য রাখবেন না।

      
প্রশ্নোত্তর

      
আসল টোকেন এখানে পেস্ট করা কি নিরাপদ?
পেজটি একবার লোড হলে অফলাইনেও চলে এবং কোথাও কিছু পাঠায় না। তবুও চালু টোকেনকে পাসওয়ার্ডের মতোই সাবধানে রাখুন: সম্ভব হলে মেয়াদোত্তীর্ণ বা টেস্ট টোকেন ব্যবহার করুন, আর কখনো প্রাইভেট কী পেস্ট করবেন না — যাচাইয়ের জন্য শুধু পাবলিক কী লাগে।

      
এই পেজ বলছে মেয়াদ শেষ, অথচ আমার অ্যাপ টোকেনটি নিচ্ছে কেন?
অনেক লাইব্রেরি ঘড়ির সামান্য পার্থক্য (প্রায়ই ৩০–১২০ সেকেন্ড) ছাড় দেয়, আর আপনার ডিভাইসের ঘড়ি সার্ভারের ঘড়ির চেয়ে আলাদা হতে পারে।

      
আমার টোকেনে পাঁচটি অংশ।
সেটি এনক্রিপ্ট করা JWE। শুধু হেডার পড়া যায়; ভেতরের তথ্য পড়তে প্রাপকের প্রাইভেট কী লাগে।

      
যাচাইয়ের সময় বলছে কী-এর ফরম্যাট ভুল।
BEGIN PUBLIC KEY দিয়ে শুরু হওয়া SPKI কী অথবা পাবলিক JWK ব্যবহার করুন। সার্টিফিকেট বা BEGIN RSA PUBLIC KEY কী আগে রূপান্তর করে নিন (যেমন openssl দিয়ে)।
