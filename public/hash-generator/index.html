What is a hash?

A hash function turns any input, a word, a document or a whole file, into a short fixed-length fingerprint. The same input always gives the same fingerprint, and even a one-character change gives a completely different one. You cannot turn the fingerprint back into the original, which is why hashes are used to check that a downloaded file was not changed, or that two files are identical.

Hashing is not encryption

Encryption can be reversed with a key. Hashing cannot be reversed at all. Read the full comparison in encoding vs encryption vs hashing.

Which algorithm should I use?

  • SHA-256, SHA-384, SHA-512 are the right choice for file checksums and integrity checks today.
  • MD5 and SHA-1 are broken for security: attackers can create two different inputs with the same hash. They are fine for spotting accidental corruption or for matching legacy systems, but never use them to sign anything.
  • Never store passwords with any of these. Fast hashes like SHA-256 and MD5 can be guessed billions of times per second. Passwords need a slow, salted algorithm such as bcrypt, scrypt or Argon2.

What is HMAC?

HMAC mixes a secret key into the hash, so only someone who knows the key can produce or check the result. APIs and webhooks use it to prove a message really came from the sender and was not changed on the way. Switch to HMAC mode and enter your key.

Is it private?

Everything is computed in your browser. SHA-1, SHA-256, SHA-384 and SHA-512 use the built-in Web Crypto API and MD5 uses code on this page. Your text, key and files are never uploaded. Files up to 100 MB are supported.

হ্যাশ কী?

হ্যাশ ফাংশন যেকোনো ইনপুট, একটি শব্দ, নথি বা পুরো ফাইলকে একটি ছোট, নির্দিষ্ট দৈর্ঘ্যের ফিঙ্গারপ্রিন্টে রূপান্তর করে। একই ইনপুটে সবসময় একই ফিঙ্গারপ্রিন্ট আসে, আর একটিমাত্র অক্ষর বদলালেই পুরোপুরি আলাদা ফল আসে। ফিঙ্গারপ্রিন্ট থেকে মূল ডেটা ফিরে পাওয়া যায় না, তাই ডাউনলোড করা ফাইল বদলে গেছে কি না বা দুটি ফাইল হুবহু এক কি না যাচাই করতে হ্যাশ ব্যবহার হয়।

হ্যাশিং এনক্রিপশন নয়

এনক্রিপশন চাবি দিয়ে উল্টানো যায়। হ্যাশিং একেবারেই উল্টানো যায় না। বিস্তারিত তুলনা পড়ুন এনকোডিং, এনক্রিপশন ও হ্যাশিংয়ের পার্থক্য গাইডে।

কোন অ্যালগরিদম ব্যবহার করবেন?

  • SHA-256, SHA-384, SHA-512 আজকের দিনে ফাইল চেকসাম ও অখণ্ডতা যাচাইয়ের জন্য সঠিক পছন্দ।
  • MD5 ও SHA-1 নিরাপত্তার জন্য ভাঙা: আক্রমণকারী একই হ্যাশের দুটি ভিন্ন ইনপুট বানাতে পারে। হঠাৎ ডেটা নষ্ট হয়েছে কি না দেখতে বা পুরোনো সিস্টেমের সাথে মেলাতে এগুলো চলে, কিন্তু কিছু সই করতে কখনো ব্যবহার করবেন না।
  • পাসওয়ার্ড সংরক্ষণে এগুলোর কোনোটিই ব্যবহার করবেন না। SHA-256 বা MD5-এর মতো দ্রুত হ্যাশ প্রতি সেকেন্ডে কোটি কোটি বার অনুমান করা যায়। পাসওয়ার্ডের জন্য দরকার bcrypt, scrypt বা Argon2-এর মতো ধীরগতির, সল্ট-যুক্ত অ্যালগরিদম।

HMAC কী?

HMAC হ্যাশের সাথে একটি গোপন চাবি মিশিয়ে দেয়, ফলে শুধু যে চাবি জানে সে-ই ফলাফল তৈরি বা যাচাই করতে পারে। API ও ওয়েবহুক এটি দিয়ে প্রমাণ করে যে বার্তাটি সত্যিই প্রেরকের কাছ থেকে এসেছে এবং পথে বদলায়নি। HMAC মোডে গিয়ে আপনার চাবি লিখুন।

এটি কি গোপনীয়?

সবকিছু আপনার ব্রাউজারেই হিসাব হয়। SHA-1, SHA-256, SHA-384 ও SHA-512-এর জন্য ব্রাউজারের Web Crypto API এবং MD5-এর জন্য এই পেজের কোড ব্যবহার হয়। আপনার টেক্সট, চাবি ও ফাইল কখনো আপলোড হয় না। ১০০ মেগাবাইট পর্যন্ত ফাইল চলে।
